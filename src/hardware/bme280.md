# BME280

## Hardware

Il modulo presenta le seguenti porte:

| SPI  | I²C  |
|------|------|
| GND  | GND  |
| 3.3V | 3.3V |
| SCK  | SDA  |
| SDO  | SCL  |
| SDI  |      |
| CS   |      |

Sulla parte superiore ci sono tre placchette, rappresentate da `_` in questo schemino: `ADR: 1___0`. Servono a scegliere l'indirizzo `I²C`: ponticellando il pad centrale verso `1` (VCC) l'indirizzo è `0x77`, verso `0` (GND) è `0x76`. Il pin `SDO` fa la stessa cosa, ma è esposto solo sul lato SPI.

In basso ci sono due coppie di placchette per i jumper di pull-up (`PU`): `CS PU` per il bus SPI e `I2C PU` per quello I²C.

Ho collegato i contatti I²C al Raspberry Pi nel seguente modo:

| I²C  | Raspberry Pi |
|------|--------------|
| GND  | GND          |
| 3.3V | 3V3          |
| SDA  | SDA1         |
| SCL  | SCL1         |

## Preparazione

Se non lo si è già fatto, abilitare [I²C](../i2c.md).

Il comando `i2cdetect -y 1` dovrebbe mostrare un numero, che rappresenta l'indirizzo: `0x76` o `0x77`. Il mio mostra `0x77`, coerente con `ADR` ponticellato su `1`.

Per leggere i dati è possibile aggiungere una libreria Python chiamata [RPi.bme280](https://pypi.org/project/RPi.bme280/). Si può installare in un ambiente virtuale Python, tenendola separata dal resto del sistema:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
mkdir -p ~/Code/bme280
```

Si può creare uno script `test_bme280.py` e fare una prova:

```python
#!/usr/bin/env -S uv run --script
#
# /// script
# requires-python = ">=3.13"
# dependencies = [
#     "rpi-bme280>=0.2.4",
# ]
# ///

import smbus2
import bme280

port = 1
address = 0x77
bus = smbus2.SMBus(port)
calibration_params = bme280.load_calibration_params(bus, address)

data = bme280.sample(bus, address, calibration_params)
print(data)
```

A questo punto basta dare:
```bash
chmod +x test_bme280.py
./test_bme280.py
```
