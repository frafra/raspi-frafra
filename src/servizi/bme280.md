# Sensore BME280

Lo script legge il [BME280](../hardware/bme280.md) e pubblica le letture su MQTT; un timer lo esegue ogni minuto.

Servono il sensore già collegato e verificato (vedi [BME280](../hardware/bme280.md)), con `uv` installato, il broker [MQTT](mqtt.md) attivo e Podman con lingering ([Requisiti](../requisiti.md)).

## Script

`~/Code/bme280/publish.py`:

```python
#!/usr/bin/env -S uv run --script
#
# /// script
# requires-python = ">=3.13"
# dependencies = [
#     "paho-mqtt>=2.2.0",
#     "rpi-bme280>=0.2.4",
# ]
# ///

import smbus2
import bme280
import paho.mqtt.client as mqtt
import platform

name = platform.node()

port = 1
address = 0x77

with smbus2.SMBus(port) as bus:
    calibration_params = bme280.load_calibration_params(bus, address)
    data = bme280.sample(bus, address, calibration_params)

client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)
client.connect("127.0.0.1", 1883)
client.loop_start()

for attr in ("temperature", "pressure", "humidity"):
    client.publish(f"{name}/bme280/{attr}", round(getattr(data, attr), 2)).wait_for_publish()
```

`wait_for_publish()` blocca lo script finché il messaggio non è stato consegnato al broker: senza, lo script potrebbe terminare prima che le pubblicazioni partano.

`platform.node()` restituisce l'hostname, che nel mio caso è `raspberrypi`: i topic sono quindi `raspberrypi/bme280/...`. Se lo cambi, aggiorna anche i sensori in Home Assistant.

La prima esecuzione va fatta con la rete disponibile, perché uv deve scaricare i pacchetti:

```bash
chmod +x ~/Code/bme280/publish.py
~/Code/bme280/publish.py
```

Dopo la prima volta si può usare `uv run --offline`.

## Servizio

`~/.config/systemd/user/bme280.service`:

```ini
[Unit]
Description=Read BME280 and publish to MQTT

[Service]
Type=oneshot
ExecSearchPath=%h/.local/bin
ExecStart=uv run --offline %h/Code/bme280/publish.py
CacheDirectory=uv
Environment=UV_CACHE_DIR=%C/uv
Environment=PYTHONDONTWRITEBYTECODE=1
NoNewPrivileges=yes
UMask=0077
TimeoutStartSec=30
PrivateUsers=yes
ProtectSystem=strict
```

Le righe meno ovvie:

- `Type=oneshot`: il servizio fa una cosa sola e termina, è il timer a richiamarlo;
- `ExecSearchPath=%h/.local/bin`: `uv` installato con lo script di Astral finisce in `~/.local/bin`, che systemd non ha nel `PATH`;
- `CacheDirectory=uv` e `UV_CACHE_DIR=%C/uv`: con gli script uv la cache deve essere scrivibile, perché uv prende un lock a ogni esecuzione; `ProtectSystem=strict` rende la home in sola lettura, quindi la cache va spostata in una directory che systemd rende scrivibile;
- `PYTHONDONTWRITEBYTECODE=1`: evita di scrivere i file `.pyc` accanto allo script (equivale a `python -B`);
- `PrivateUsers=yes`, `ProtectSystem=strict`, `NoNewPrivileges=yes`, `UMask=0077`: riducono i privilegi e l'accesso al filesystem al minimo necessario;
- `TimeoutStartSec=30`: una lettura I²C dura pochi istanti, se supera i 30 secondi c'è un problema.

L'elenco completo delle opzioni è in [systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html).

### Alternativa con progetto Python

Se preferisci un progetto classico con `pyproject.toml` (`uv init --bare`, `uv add rpi-bme280 paho-mqtt`), il servizio diventa:

```ini
WorkingDirectory=%h/Code/bme280/
ExecStart=uv run --no-sync --offline python -B publish.py
```

Qui `--no-sync` ha effetto, quindi non serve rendere scrivibile la cache, ma va fatto `uv sync` almeno una volta.

## Timer

`~/.config/systemd/user/bme280.timer`:

```ini
[Unit]
Description=Sample BME280 every minute

[Timer]
OnCalendar=*-*-* *:*:00
AccuracySec=1s
Persistent=true
Unit=bme280.service

[Install]
WantedBy=timers.target
```

`OnCalendar` esegue il servizio allo scoccare di ogni minuto; `Persistent=true` recupera l'esecuzione persa se il Raspberry era spento.

## Attivazione e verifica

```bash
systemctl --user daemon-reload
systemctl --user enable --now bme280.timer
systemctl --user list-timers bme280.timer
journalctl --user -u bme280.service -n 20 --no-pager
```

Se `journalctl` non mostra errori, i dati dovrebbero essere su MQTT:

```bash
podman exec mosquitto mosquitto_sub -h 127.0.0.1 -t "$(hostname)/bme280/#" -v
```

In Home Assistant si aggiungono tre sensori MQTT che leggono quei topic (vedi [Home Assistant](homeassistant.md)).
